# medref-pipeline — Project Requirements & Implementation Spec

## 1. Objective

Build a batch data pipeline and serving API for **drug reference data**. The pipeline ingests a periodic feed of medication records (CSV), validates it against a schema contract, deduplicates and enriches it with ATC classification codes, and loads it idempotently into PostgreSQL. A versioned FastAPI service exposes the served data over REST.

The system must be runnable end-to-end locally with a single command via docker-compose.

---

## 2. Tech stack & constraints

- **Language:** Python 3.11+
- **API framework:** FastAPI
- **Validation:** Pydantic v2
- **Database:** PostgreSQL 16
- **DB access:** SQLAlchemy 2.x (core or ORM) or `psycopg` — implementer's choice, must use parameterized queries
- **Transforms:** Polars (preferred) or pandas
- **Testing:** pytest + FastAPI `TestClient`
- **Containerization:** Docker + docker-compose
- **CI:** GitHub Actions (lint + test)
- **Dependency management:** `pyproject.toml` (uv or Poetry or pip-tools — implementer's choice)
- **Lint/format:** ruff

Constraints:
- No cloud dependencies required to run locally. Object storage is simulated by a local directory.
- Transforms run in-process (single node). Code should be structured so logic is portable to a distributed engine later, but do not add Spark.
- No streaming. The pipeline is batch, triggered manually via CLI.

---

## 3. Data model

PostgreSQL schema. Four tables.

### `manufacturers`
| column | type | notes |
|---|---|---|
| manufacturer_id | SERIAL | PK |
| name | TEXT | unique, not null |

### `atc_reference`
| column | type | notes |
|---|---|---|
| atc_code | TEXT | PK (e.g. "M01AE01") |
| atc_description | TEXT | not null |

### `medications` (serving table)
| column | type | notes |
|---|---|---|
| pzn | TEXT | PK, exactly 8 numeric chars, leading zeros preserved |
| name | TEXT | not null |
| active_ingredient | TEXT | not null |
| dosage_form | TEXT | not null, constrained set |
| strength | TEXT | not null (e.g. "400mg") |
| prescription_only | BOOLEAN | not null |
| price | NUMERIC(10,2) | not null, >= 0 |
| manufacturer_id | INT | FK → manufacturers |
| atc_code | TEXT | FK → atc_reference, nullable |

Allowed `dosage_form` values: `tablet`, `capsule`, `solution`, `injection`, `cream`, `drops`, `spray`.

### `pipeline_runs` (lineage / run manifest)
| column | type | notes |
|---|---|---|
| run_id | UUID | PK |
| source_file | TEXT | not null |
| rows_in | INT | rows read from feed |
| rows_out | INT | rows loaded to serving |
| rows_rejected | INT | rows sent to dead-letter |
| started_at | TIMESTAMPTZ | not null |
| finished_at | TIMESTAMPTZ | nullable until complete |
| status | TEXT | `running` \| `success` \| `failed` |
| content_hash | TEXT | hash of the loaded dataset |

## 4. Input data (synthetic, generated by the project)

Provide a generator script or committed fixture files under `data/`. All data is synthetic; ATC codes should be real WHO ATC values.

- **`feed_v1.csv`** — initial full feed, 50–200 rows. Columns: `pzn, name, active_ingredient, dosage_form, strength, prescription_only, price, manufacturer, atc_code`.
- **`feed_v2_delta.csv`** — a later feed containing: some brand-new PZNs, and some existing PZNs with changed fields (e.g. price/name). Used to verify upsert + idempotency.
- **`feed_broken.csv`** — same columns, but with rows that each violate one validation rule: missing required field, non-numeric PZN, wrong-length PZN, `dosage_form` outside allowed set, non-boolean `prescription_only`, negative `price`, duplicate PZN.
- **`atc_reference.csv`** — `atc_code, atc_description` pairs (real WHO ATC codes) for enrichment.

Note the feed uses a denormalized `manufacturer` name column; the pipeline normalizes it into the `manufacturers` table.

## 5. Functional requirements — pipeline

### 5.1 Ingestion (`src/ingest.py`)
- Read the feed CSV as a stream (generator), not fully into memory.
- Validate each row against the Pydantic feed-row model (see 5.2).
- Valid rows are yielded downstream.
- Invalid rows are written to a **dead-letter file** (`dead_letter/<run_id>.csv`) with an added `rejection_reason` column. Ingestion must not abort on an invalid row.

### 5.2 Schema contract (`src/schema.py`)
Pydantic v2 models:
- `FeedRow` — the raw incoming row. Field validators enforce:
  - `pzn`: string, exactly 8 characters, all digits (leading zeros preserved — never coerce to int).
  - `dosage_form`: must be in the allowed set.
  - `prescription_only`: strict bool (accept `true/false`, `1/0`, `yes/no`; reject anything else).
  - `price`: Decimal, >= 0.
  - `atc_code`: optional, must match ATC format if present.
  - All required fields present and non-empty.
- `Medication` — the clean/serving model returned by the API.

A validation failure raises with a clear, specific reason (used as `rejection_reason`).

### 5.3 Transform (`src/transform.py`)
- **Deduplicate** on `pzn`. If duplicates exist within a feed, keep the last occurrence (or by an explicit version field if added). Deduplication happens before any join so the load stays 1:1 on PZN.
- **Normalize** `manufacturer`: resolve each manufacturer name to a `manufacturer_id`, inserting into `manufacturers` if new.
- Return clean records ready for enrichment + load.

### 5.4 Enrichment (`src/enrich.py`)
- Attach `atc_description` context is not stored on `medications`, but the `atc_code` FK must resolve. Ensure every `atc_code` present in the feed exists in `atc_reference`; upsert missing ATC rows from `atc_reference.csv`.
- Model the ATC source behind a function `lookup_atc(code)` so it can later point at a remote terminology API. When called as if remote (configurable flag), wrap calls with **retry: exponential backoff + jitter, a maximum retry count, and honor a `Retry-After` value**. Offline default reads from the local CSV.

### 5.5 Load (`src/load.py`)
- Write the clean batch to a **staging table** (`medications_staging`).
- Publish by **atomically swapping** staging into `medications` — either inside a single transaction (truncate+insert or upsert) or via table rename. A failure mid-load must never leave the serving table partially written.
- The load must be **idempotent**: running the same feed twice results in identical serving-table contents (no duplicates, no drift).
- Use upsert semantics (`INSERT ... ON CONFLICT (pzn) DO UPDATE`) so a delta feed updates changed rows and inserts new ones.

### 5.6 Lineage (`src/lineage.py`)
- At pipeline start, insert a `pipeline_runs` row with `status='running'`, `source_file`, `started_at`.
- At end, update `rows_in`, `rows_out`, `rows_rejected`, `finished_at`, `content_hash`, and `status`.
- On failure, set `status='failed'` and still record counts collected so far.

### 5.7 Orchestration (`src/pipeline.py`)
- A single CLI entrypoint: `python -m src.pipeline --feed data/feed_v1.csv`.
- Runs stages in order: ingest → transform → enrich → load, with lineage wrapping the whole run.
- Each stage is a pure, independently-callable function. The pipeline composes them.
- Exit code 0 on success, non-zero on failure.

## 6. Functional requirements — API (`src/api/main.py`)

Versioned under `/v1`. All responses use Pydantic response models. Reads from the `medications` serving table.

| Method | Path | Behavior |
|---|---|---|
| GET | `/v1/medications` | List medications. Optional query filters: `dosage_form` (str), `prescription_only` (bool). Supports `limit` (default 50, max 500) and `offset` pagination. |
| GET | `/v1/medications/search` | `?q=<term>` — case-insensitive match on `name` or `active_ingredient`. **Must be declared before the `/{pzn}` route.** |
| GET | `/v1/medications/{pzn}` | Single medication by PZN. 404 if not found. |
| GET | `/v1/stats/dosage-forms` | Count of medications grouped by dosage form. Returns `{form: count}`. |
| GET | `/health` | Liveness/readiness — returns 200 + db connectivity status. |

Requirements:
- Correct HTTP status codes (200, 404, 422 on invalid query params).
- Pagination metadata in list responses (total count, limit, offset).
- Response models must include all serving fields.

### 6.1 Optional endpoint (implement only if core is complete)
| Method | Path | Behavior |
|---|---|---|
| POST | `/v1/ask` | Body `{question: str}`. Retrieves relevant medication rows and calls the Anthropic API to answer in natural language, citing the PZNs used. Requires `ANTHROPIC_API_KEY` env var. |

## 7. Non-functional requirements

- **Idempotency:** re-running any feed yields identical serving state. Enforced by a test.
- **Fail-fast at the boundary:** malformed input never reaches the serving table; it is rejected to dead-letter with a reason. The run continues for valid rows.
- **Observability:** structured logging (JSON or key-value) at each stage with row counts; the `pipeline_runs` table is queryable for run history.
- **Correctness:** parameterized SQL only. No string-interpolated queries.
- **Config:** DB connection and flags via environment variables (`.env` supported), not hardcoded.
- **Reproducibility:** `docker-compose up` starts Postgres + API; a documented command runs the pipeline against the running DB.

## 9. Testing requirements

- **`test_schema.py`** — each validation rule accepts valid input and rejects each invalid case with the expected reason.
- **`test_ingest.py`** — valid rows pass; invalid rows land in dead-letter with reasons; ingestion does not abort on bad rows.
- **`test_transform.py`** — deduplication keeps the correct record; manufacturer normalization produces stable IDs.
- **`test_load.py`** — atomic swap leaves a complete table; a simulated mid-load failure leaves the prior serving table intact.
- **`test_pipeline.py`** — full end-to-end run on `feed_v1.csv`; **running twice yields identical serving contents (idempotency)**; running `feed_broken.csv` loads only valid rows and records `rows_rejected` in `pipeline_runs`.
- **`test_api.py`** — every endpoint, including 404 on unknown PZN, empty search, filter combinations, pagination bounds, and 422 on invalid params.

CI runs ruff + pytest on every push.

## 13. Build order

1. Scaffold: repo, `pyproject.toml`, docker-compose, migrations, config, db.
2. Generate synthetic data (all four CSVs including the broken one).

5. `transform.py` (dedup + normalize) + `test_transform.py`.
6. `enrich.py` (ATC + retry wrapper).
7. `load.py` (staging + atomic swap + upsert) + `test_load.py`.
8. `lineage.py` + `pipeline.py` CLI + `test_pipeline.py`.
9. `api/main.py` + `test_api.py`.
10. CI workflow, README.
